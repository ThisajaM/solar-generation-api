## Understanding / viva notes

These are project-specific points to review and explain in the student's own words; their presence does not establish personal understanding:

- **Separate GenerationReading collection:** preserves timestamped history independently of installation metadata; `(installation, timestamp)` is unique and the API does not expose reading update/delete.
- **Last reading:** queries `GenerationReading` for the installation in descending timestamp order instead of relying on a mutable cached value on `SolarInstallation`.
- **District versus national JWT scope:** the token's role/scope and database user are checked; national analysts may read across jurisdictions, while district analysts are restricted to their district. Device writes are tied to their own installation; installation administrators have separate management grants.
- **Pagination metadata:** offset responses use the filtered count, requested page and limit to calculate total pages and next/previous links. Cursor and snapshot modes have different consistency limits described in the README.
- **ETag / 304:** the server hashes a response representation to form an ETag; a matching conditional GET can return a bodyless 304, while a failed strong `If-Match` comparison returns 412.
- **District summary:** fresh non-future readings contribute current power; valid consecutive cumulative-energy deltas within the Asia/Colombo day contribute reported energy. Gaps, resets and incomplete coverage are surfaced rather than estimated away.
- **Vercel MongoDB connection reuse:** warm serverless invocations reuse an established Mongoose connection or await an in-flight connection promise; failed attempts clear that promise so a later request can retry.
